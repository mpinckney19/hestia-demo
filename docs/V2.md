# Hestia V2: Social Media-Based Advocacy

## Vision

Demonstrate that an AI can understand a person from their social media presence and then advocate on their behalf - across any social coordination scenario.

The key insight: the AI learns *who someone is*, not their preferences for a specific task. That understanding then applies to whatever scenario needs mediating.

### Use Cases

The same social profile can power different advocate scenarios:

- **Dinner / night out planning** - "Plan a Friday night for two people"
- **Trip planning** - "Plan a weekend getaway that works for both"
- **Gift recommendations** - "What gift would Person A appreciate from Person B?"
- **Event coordination** - "Find a concert/show both would enjoy"
- **Group scheduling** - "When should these people meet?"
- **Splitting decisions** - "How should they divide costs fairly?"

The posts don't change. The scenario does.

## User Flow

```
┌─────────────────────────────────────────────────────────┐
│  1. GENERATE                                            │
│  ┌─────────────┐          ┌─────────────┐              │
│  │  Person A   │          │  Person B   │              │
│  │  50 posts   │          │  50 posts   │              │
│  └─────────────┘          └─────────────┘              │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  2. SELECT SCENARIO                                     │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐    │
│  │ Friday Night │ │  Weekend Trip │ │    Gifts     │    │
│  └──────────────┘ └──────────────┘ └──────────────┘    │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  3. ADVOCATES COORDINATE                                │
│  ┌─────────────┐    negotiate    ┌─────────────┐       │
│  │  Advocate A │◄───────────────►│  Advocate B │       │
│  │  (reads A's │                 │  (reads B's │       │
│  │   posts)    │                 │   posts)    │       │
│  └─────────────┘                 └─────────────┘       │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  4. AGREEMENT                                           │
│  Final plan that works for both people                  │
└─────────────────────────────────────────────────────────┘
```

**Step 1**: Generate two personas with 50 posts each. Display profiles to user.

**Step 2**: User selects a scenario. This is just a simple directive passed to the advocates.

**Step 3**: Advocates read their user's posts, infer who they are, and negotiate with each other.

**Step 4**: Advocates reach agreement. Display the result.

## Current State (V1)

The AI receives clean, task-specific data:
```json
{
  "preferences": {
    "cuisines": ["Japanese", "Italian"],
    "priceRange": "moderate",
    "socialStyle": "intimate"
  }
}
```

**Problem**: Data is pre-structured for the task. No real inference required.

## V2 Approach

Keep it simple: **50 posts per person**. That's it.

Each post is a snapshot of social media activity - the AI reads through them and builds a picture of who this person is. That picture then informs whatever scenario needs mediating.

| Instead of task-specific data... | AI infers from posts... |
|----------------------------------|------------------------|
| `cuisines: ["Japanese"]` | "Finally tried that ramen spot on St Marks 🍜" |
| `budget: "moderate"` | Mix of splurges and "broke until Friday" posts |
| `socialStyle: "intimate"` | "so crowded we couldn't even talk" complaint |
| `schedule: "night owl"` | Posts at 1am, complaints about early meetings |
| `interests: ["hiking"]` | Trail photos, outdoor gear mentions |
| `travel_style: "adventurous"` | Hostel stays, off-the-beaten-path locations |

The same posts inform dinner planning, trip planning, gift ideas, etc.

## Data Model

### SocialProfile

```typescript
interface SocialProfile {
  id: string;
  name: string;
  bio: string;             // Short, like a real bio: "Designer @ Figma | BK | 🍕"
  posts: Post[];
}
```

### Post

```typescript
interface Post {
  id: string;
  timestamp: string;       // ISO date
  content: string;         // ~50 words describing the post + caption
  location?: string;       // Optional location tag
  tags?: string[];         // Optional hashtags or tagged people
}
```

### Example Bio

```
"Product designer @Stripe. Williamsburg. Coffee snob. Will travel for tacos."
```

Short, punchy, indirect signals only. The agent has to dig through posts for the real picture.

## MCP Tools (V2)

Just three tools. Keep it elegant.

### `get_profile`
Get the user's name and bio.
```
Parameters: none
Returns: { name, bio }
```

### `get_posts`
Browse posts with optional filtering.
```
Parameters:
  - count?: number (default 10, max 50)
  - offset?: number (for pagination)
  - before?: string (ISO date)
  - after?: string (ISO date)
Returns: Post[]
```

### `search_posts`
Search through post content.
```
Parameters:
  - query: string
  - limit?: number (default 10)
Returns: Post[] (matching posts)
```

The agent can:
1. Get profile for basic context
2. Browse recent posts to get a feel for the person
3. Search for specific topics ("food", "restaurant", "friday", "budget", etc.)

## Tension Points

Two different people naturally have different lifestyles. The AI discovers where they align and conflict by reading their feeds.

Examples of lifestyle differences that create negotiation opportunities:

**Budget**: One posts from upscale spots, another jokes about being broke
**Energy**: One loves crowded energy, another seeks quiet corners
**Schedule**: One's a night owl, another's up at 6am for the gym
**Food**: One posts BBQ and steakhouses, another shares plant-based recipes
**Travel**: One stays at boutique hotels, another backpacks and hostels
**Planning**: One's spontaneous, another needs everything scheduled

These aren't "tensions to engineer" - they're natural differences between any two people. The AI's job is to find common ground.

## System Prompt (V2)

Keep it simple. The AI is smart enough to figure out how to investigate.

```
You are an AI advocate representing {name}.

You have access to their social media posts through these tools:
- get_profile: Get their name and bio
- get_posts: Browse their recent posts
- search_posts: Search their posts for specific topics

Your goal: {scenario}

Speak as an advocate ("My user would..."), not as the user. Work with the other advocate to find a solution that works for both people.
```

That's it. The scenario is just a one-liner:

| Scenario | Directive |
|----------|-----------|
| Dinner planning | "Plan a Friday night out in NYC that works for both people." |
| Trip planning | "Plan a weekend trip that works for both people." |
| Gift recommendation | "Help each person find a gift the other would appreciate." |
| Event coordination | "Find an event or activity both people would enjoy this weekend." |

The AI figures out what to search for, what patterns matter, how to negotiate. We don't need to prescribe it.

## Generation Approach

Don't over-engineer the generation. The prompt should simply ask for:

> "Generate 50 typical social media posts for a person living in NYC."

That's it. Let the posts be whatever a real person would post - work stuff, food, friends, complaints, jokes, photos, life updates. The AI advocate's job is to find what's relevant for whatever scenario comes up.

**What we tell the generator:**
- Create two NYC-based people with distinct personalities
- Give each 50 realistic social media posts spanning recent months
- Posts should feel authentic - the mix of mundane, interesting, personal, random
- Each person should have a consistent voice and lifestyle that comes through

**What we don't tell the generator:**
- Specific preference categories to include
- Signal/noise ratios
- What scenarios the posts will be used for
- What the AI should be able to infer

The posts should pass the "would a real person post this?" test. The same profile works for dinner planning, trip planning, gift recommendations, or any other social coordination.
